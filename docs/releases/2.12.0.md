# bazis-mcp 2.12.0

How each tool works and what it refuses is in the guide,
[bazis/contrib/mcp/AGENTS.md](../../bazis/contrib/mcp/AGENTS.md).

## Features

- **`create_project` normalizes the name of the product.** `name` becomes the project
  package as the name of a directory does (`scaffold.package_name`): `master-na-chas` and
  `Master-na-chas` are `master_na_chas`, `42 shop` is `project_42_shop`, a keyword or a
  module of the server gets the suffix `_project` (`class_project`). The result, `.env`,
  `project.env` and `next_steps` name the package. A name that would hide a module of the
  Python of the project is still refused after `.venv` is installed.
- **The rules of every project** (`bazis://rules`):
  - the limit of the uploads stays a few megabytes, also for the photos of phones
    (bazis-front 0.10 reduces a larger image in the browser, `fitImage`), and with bazis
    2.22 the agent sets `BS_BAZIS_API_MAX_BODY_SIZE` in `project.env` a megabyte above it;
  - `changes.user` of a guest in `validate_item` and in a public action or transit is the
    `AnonymousUser`, never None: the code tests `is_authenticated`;
  - a picker of the users of a role (`roles__slug`) needs
    `router.register('bazis.contrib.permit.router')` in the root router module, which makes
    the roles a public catalog (said in Left for you); the skeleton's `router.py` names it
    in a comment.
- **The rules of the frontend** (`bazis://rules/frontend`), for bazis-front 0.10.0:
  - the image of the scenarios is `photo.png` of the template, another file of the product
    is written beside it in `frontend/e2e/fixtures/`, never by a script or a test;
  - a text with `, ` in a flow mapping of a spec goes in quotes (P002);
  - a choice of the payload of a transit is the `TextChoices` of the model, which bazis
    2.22 labels (P037);
  - one shot of each screen is looked at, its first one (another only where the report
    names an error or a warning), and after a change only those of the screens it touched;
    the step of the screenshots of a new product and the task of a change say the same;
  - the specs say what was code of the product: a section shown by status (`when`, S059),
    the values a form starts with (`values`, S060), the items of a picker (`filter`,
    `filters`, S061), several files (`type: file`, `many: true`), a move with a payload and
    what a role may not do (`transit_absent`, `action_absent: edit`, `field_readonly`);
  - the update to 0.10 (`e2e/fixtures/photo.png`, P002, P017, a `move` instead of a transit
    run on a card only for its payload), `bazis_front version`;
  - the records of `e2e_data` pass the validators of the models, and it runs before every
    `npm run e2e`.

## Changes

- **The catalog** describes the latest releases: bazis 2.22.0 (it was 2.21.0: the labels of
  the choices of a payload, `BAZIS_API_MAX_BODY_SIZE`) and bazis-front 0.10.0 (it was
  0.9.0: S059–S061, P037, `photo.png` and `fitImage` in the registry of its assets); the
  other packages are unchanged.
- The instructions of the server, the description of `create_project`, the prompt
  `new_project` and the guide say "the name of the product in Latin letters" instead of a
  slug.
- `project.database_server(database, default=None)`: without `database` and without a
  server named by the environment it returns `default` when one is given (bazis-cli passes
  localhost:5432 for `bazis new`); `create_project` passes none and refuses as before.
- The rules are shorter where they explained what the guides say, so that the result of
  `create_project` for a product keeps a tenth of the limit of the clients free.

## Requirements

- **A new project requires `bazis>=2.22.0`** (it was 2.21.0) and, with a frontend,
  **`bazis-front>=0.10.0`** (it was 0.9.0); the extra `test` requires `bazis>=2.22.0`.

## Upgrading

- A client that passed a `name` such as `master-na-chas`, refused by 2.11, gets the
  project package `master_na_chas`; the result says `name`. A `name` of a module of the
  server (`django` where the server has it) is `django_project` instead of a refusal.
- `scaffold.package_name` takes the name as a text too; bazis-cli and its evals, which pass
  a directory, work as before.
- The projects already created are not rewritten: an older product takes bazis-front 0.10
  with `pip install -U bazis-front` and `bazis_front update`, as the rules say.

## Known limitations

- `bazis new` of bazis-cli 2.6.1 still writes `.env` without the server chosen (see 2.11.0);
  bazis-cli 2.7.0 passes it through `database_server(..., default=...)` and requires this
  release. Its tests `test_new_with_a_language` and `test_requirements_are_the_latest_releases`
  fail with 2.6.1 until then.
