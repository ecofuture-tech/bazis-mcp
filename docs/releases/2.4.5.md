# bazis-mcp 2.4.5

## Features

- Tools of the frontend layer made by bazis-front, read-only like the others and run with
  the Python of the project: `front_check(layer)` (the issues of the specs,
  `bazis_front check --json`), `front_status()` (the stale parts of the frontend, from the
  checks `front.*` of `bazis_doctor`, without Node) and `front_catalog()` (the assets that
  `bazis_front init` and `add` copy, with the capabilities and assets they require). Without
  bazis-front, or with it not in `INSTALLED_APPS`, they return `checked: false` with the
  reason.
- The prompt `build_frontend`.
- `scripts/update_catalog.py` adds bazis-front to the catalog, with its registry of the
  assets, once it is released; a package that is not on PyPI is left out.

- `package_guide(name, section)`: the result lists the titles of the `sections` of the
  AGENTS.md, and a guide longer than 30,000 characters comes as its introduction with
  `complete: false` instead of whole (the guide of bazis-front went over the output limit
  of Claude Code, which saved it to a file); `section` returns the text of one section,
  and a section longer than the limit is split into parts.

## Changes

- The installed packages of `list_packages`, `package_guide`, the resource of the guides
  and `project_info` are those of the Python of the project (`--python`, else `.venv`),
  read in a new process at every call like the other project tools: bazis-cli runs the
  server with its own Python, whose packages were reported as those of the project, and a
  package installed or upgraded while the server ran kept its old version and guide.
- A checkout of bazis-mcp installed from its directory is built again after every commit
  (`[tool.uv] cache-keys`): uv reused the build of an older commit, with its catalog.

- The catalog describes the latest releases: bazis 2.11.0 (the language of each request,
  the default `LANGUAGE_CODE` `en`; the relationships link and include only the objects the
  user can see, through `restrict_queryset`; filters, sorting and search reach only the
  fields of the route; `validate_item` checks the invariants of an item on every write;
  error pointers into the request document; the checks `bazis.W003` to `W007`),
  bazis-users 2.8.0 (the token endpoint module `bazis.contrib.users.token`, `users.E002`,
  the opt-in `UserLanguageMixin`), bazis-permit 2.8.0 (selectors through many-to-many and
  reverse relations, the query scope per user, 404 for an item the user cannot view;
  `BAZIS_PERMIT_RELATIONS_VIEW_CHECK` is deprecated), bazis-statusy 2.7.0,
  bazis-uploadable 2.6.2, bazis-author 2.4.1, bazis-ws 2.5.1, bazis-bg 2.5.0 and
  bazis-authing 2.6.0, with the guides that answer what the trial products asked.
