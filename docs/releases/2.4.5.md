# bazis-mcp 2.4.5

## Features

- Tools of the frontend layer made by bazis-front, read-only like the others and run with
  the Python of the project: `front_check(layer)` (the issues of the specs,
  `bazis_front check --json`), `front_status()` (the stale parts of the frontend, from the
  checks `front.*` of `bazis_doctor`, without Node) and `front_catalog()` (the assets that
  `bazis_front init` and `add` copy, with the capabilities and assets they require). Without
  bazis-front, or with it not in `INSTALLED_APPS`, they return `checked: false` with the
  reason.
- The prompt `build_frontend`.
- `scripts/update_catalog.py` adds bazis-front to the catalog, with its registry of the
  assets, once it is released; a package that is not on PyPI is left out.

- `package_guide(name, section)`: the result lists the titles of the `sections` of the
  AGENTS.md, and a guide whose result would be over 40,000 bytes of JSON (measured with
  the manifest, as the result is sent) comes as its introduction with `complete: false`
  instead of whole (the guide of bazis-front went over the output limit of Claude Code,
  which saved it to a file; the guide of the core with its manifest is over the limit
  too); `section` returns the text of one section, and a section over 30,000 bytes of
  JSON (an introduction: less the manifest) is split into parts, a line longer than that
  too.

## Changes

- The installed packages of `list_packages`, `package_guide`, the resource of the guides
  and `project_info` are those of the Python of the project (`--python`, else `.venv`),
  read in a new process at every call like the other project tools: bazis-cli runs the
  server with its own Python, whose packages were reported as those of the project, and a
  package installed or upgraded while the server ran kept its old version and guide. A
  Bazis older than 2.4 (no `bazis.core.introspect`) is listed with its versions and the
  guides of the catalog; a Python of the project that cannot be run is an error of the
  tools and of the resource of the guides, with the reason.
- A checkout of bazis-mcp installed from its directory is built again after every commit
  (`[tool.uv] cache-keys`): uv reused the build of an older commit, with its catalog.

- The catalog describes the latest releases: bazis 2.13.0 (the language of each request;
  relationships, `included`, filters, sorting and search reach only what the user can see
  and the fields of the route; `validate_item` checks the invariants of an item on every
  write; error pointers into the request document; fields outside the write schema and
  blank texts are refused; `bazis_doctor` runs the checks of the database), bazis-permit
  2.9.1 and bazis-statusy 2.9.1 (roles, permissions, statuses and transits declared in
  `<app>/roles.py` and `<app>/workflow.py`, applied by `migrate`), bazis-test-utils 2.5.0
  (a pytest plugin: triggers and declarations in the test database), bazis-users 2.8.0,
  bazis-ws 2.6.0 (`notify()` and `publish_changed()`, the socket routed through the
  router), bazis-uploadable 2.6.2, bazis-author 2.4.1, bazis-bg 2.5.0 and bazis-authing
  2.6.0, with the guides that answer what the trial products asked.
