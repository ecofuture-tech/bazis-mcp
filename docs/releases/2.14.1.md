# bazis-mcp 2.14.1

## Fixed

- **The guests no longer read the roles of a product with a picker of the users of a
  role.** The rules of every project (`bazis://rules`) said, since 2.12.0, that such a
  picker (`roles__slug`) needs `router.register('bazis.contrib.permit.router')`, which makes
  the roles a public catalog. A product whose guests may see nothing but its public screens
  followed it, and a guest read the slugs and names of the roles
  (`GET /api/v1/permit/role/` without a token, 200). The filter only needs a route set of the
  roles: the rules now give the one of the app `users/`,
  `class RoleRouteSet(UserRequiredRouteBase, RoleRoute)` registered in `users/router.py`,
  which only the signed-in users read (401 for a guest), and never the router of
  bazis-permit, also where the hint of S061 names it. The comment of the root router module
  of the skeleton says the same.

## Changes

- **The catalog** describes the latest releases: bazis-front 0.11.1 (it was 0.11.0: the
  thumbnail of a content already read is no longer broken in the dev server, `{run}` in the
  texts of the scenarios gives an item with a unique field another value at every run, and
  `expectValues` compares a run of spaces as one space); the other packages are unchanged.

## Requirements

- A new project with a frontend requires **`bazis-front>=0.11.1`** (it was 0.11.0); it still
  requires `bazis>=2.25.0`, and `add_packages` adds bazis-uploadable as
  `bazis-uploadable>=2.9.0`.

## Upgrading

- The projects already created are not rewritten. A product that registered
  `bazis.contrib.permit.router` for the picker of a role replaces it with the route set of
  the rules in `users/routes.py` and `users/router.py`, then exports the contract again
  (`bazis_front contract`): the resource `permit.role` keeps its type and its fields, so the
  specs and the screens are unchanged.
- An older product takes bazis-front 0.11.1 with `pip install -U bazis-front` and
  `bazis_front update`, as the rules say.
