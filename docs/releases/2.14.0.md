# bazis-mcp 2.14.0

## Changes

- **The catalog** describes the latest releases: bazis 2.25.0 (it was 2.24.0: `file_meta=` of
  `http_post` declares the header `X-Bazis-Meta` of an answer that is a file, `file_answer`
  sends the file with its meta, and CORS exposes the header; the manifest names
  `file_answer`), bazis-uploadable 2.9.0 (it was 2.8.0: a guest reads and downloads the files
  of `files_visible` of the objects that a route set serving guests shows him;
  `uploadable.W003` names such a route set without a `restrict_queryset` of its own) and
  bazis-front 0.11.0 (it was 0.10.2: the contract of format 12, the meta of a file next to
  `{filename}` in the result of a form, S053, the filter of a field of an entity for its
  pickers, S061, the files of a public screen, S062, `display: image`, the days of the
  browser and the lookups in the filter of a list and a tile, S014, S063 of a create form
  that leaves out a required boolean, and `python -m bazis.contrib.front.spec.lint`); the
  other packages are unchanged.
- **The rules of every project** (`bazis://rules`): a test of parallel requests asks that at
  least one of them succeeds; a guest reads the files of `files_visible` of the objects that
  a route set shows him (bazis-uploadable 2.9, `uploadable.W003`), never by a `/media` URL.
- **The rules of the frontend** (`bazis://rules/frontend`): the specs of 0.11 say the meta of
  an exported file (`file_meta` of `http_post`: a flat model, no Enum, under 4096 bytes,
  S053), the photos of public objects (`display: image`, S062) and the days of the browser in
  a `filter` (S014), and after the update to 0.11 a custom screen or test that did them
  becomes the spec; an agent with a shell lints each file of the specs it writes with
  `python -m bazis.contrib.front.spec.lint` before `front_check`.
- The rules say shorter what they said in more words (the pytest plugin, the languages and
  `bazis_messages make`, the temporary files, the app `users/`, the link of the form of an
  action, the files of the scenarios, the prettier, a machine without Node.js) and
  leave to the guide of bazis-front an example of a quoted YAML text and two notes of the
  updates to 0.5 and 0.6 (the replacements of `useTransitsOf`, an extension of a tile on a
  phone), so that the result of `create_project` for a product, with the new rules, still
  keeps a tenth of the limit of the clients free.

## Requirements

- **A new project requires `bazis>=2.25.0`** (it was 2.24.0) and, with a frontend,
  **`bazis-front>=0.11.0`** (it was 0.10.2); `add_packages` adds bazis-uploadable as
  `bazis-uploadable>=2.9.0`, the release of the catalog; the extra `test` requires
  `bazis>=2.25.0`.

## Upgrading

- The projects already created are not rewritten. An older project takes bazis 2.25 with
  `pip install -U bazis` (a route without `file_meta` answers as before) and
  bazis-uploadable 2.9 with `pip install -U bazis-uploadable`: the files of `files_visible`
  of the route sets that already serve guests become public for the objects that their
  `restrict_queryset` shows a guest, and a guest gets 404 instead of 401 from the item and
  the download of a file that is not public; run `run_doctor` and restrict the route sets that
  `uploadable.W003` names.
- An older product takes bazis-front 0.11 with `pip install -U bazis-front` and
  `bazis_front update`, as the rules say, then `bazis_front contract` (format 12: `check`
  reports C002 until then); a filter of a date-time by a day without a time other than
  `__gte` and `__lt` is now S014, and code that read the result of `useActionFile` as the
  name reads `.name`.
