# bazis-mcp 2.4.1

## Fixes

- **The project tools showed the project as it was when the server started.** The server
  loaded the project once, so after an agent changed models, routes or settings,
  `project_info` and `run_doctor` reported the old code until the MCP client restarted the
  server. They now run `bazis_introspect` and `bazis_doctor` in a new process at every call
  (`python -m django` in the project directory), and the
  server no longer imports the project: a project that fails to load or prints to stdout
  cannot affect the server.
- `--python` sets the Python of the project; by default the server uses `.venv` of the
  project directory or of its parent, else its own Python.
- Packages installed while the server runs are seen by `list_packages` and `package_guide`.
