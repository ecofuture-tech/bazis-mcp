# bazis-mcp 2.10.0

How each tool works and what it refuses is in the guide,
[bazis/contrib/mcp/AGENTS.md](../../bazis/contrib/mcp/AGENTS.md).

## Features

- **The users of a team are labeled by name.** `add_packages` writes the app `users/` with
  the route set of the team (`users/routes.py`: a search by the username and the names, a
  signed-in user views every active user and changes only himself; `users/router.py`) when
  it adds bazis-users, and lists the files in `files`; a file the project has already is
  kept. The rules of every project (`bazis://rules`) say that the root router module
  registers `router.register('users.router')`, which also declares the token endpoint
  (`users.E002`). Without a route of the user resource the frontend labels the author of a
  status, the assignee and the watchers by the start of an id.
- **The rules of bazis-front 0.8.0** (`bazis://rules/frontend`): the payload field of a
  decimal in a spec is `string` (`number` is allowed too) and an Enum or a Literal is
  `string`, never `json` (P017); a text of the YAML with `: ` is in quotes and `summary` of
  the product may be a map of languages; the files that a scenario uploads are in
  `frontend/e2e/fixtures/`; the top bar is cut by links and a group is shared by its row
  and its menu; `front_check` warns P036 for a project whose users have no route.

## Changes

- **The catalog** describes bazis-front 0.8.0 (it was 0.7.0: the checks P036 and the
  others of the release, the assets and the guide); the other packages are unchanged.
- **The cache of a new project is the Redis of the server.** `create_project` writes
  `BS_CACHES__DEFAULT__LOCATION` of `.env` as the environment of the bazis-mcp process sets
  it (as it does for the host and the port of PostgreSQL), else `redis://localhost:6379/0`
  as before; the answer has it as `cache`, without a password. The tests and the backend
  of a product no longer land in a Redis database that the server does not use.
- **A product is in the language of its description alone.** `create_project(language=...)`
  writes `BS_LANGUAGES` with that language only when the bazis-front installed in the
  project has a dictionary of it (`en` and `ru`); English is added, as the fallback, to a
  language without one (and to a backend without bazis-front). It was the language and
  English: a product in Russian got an English version that nobody asked for, and the
  frontend check made its specs list both. The rules of the languages (`bazis://rules`)
  and the task of a new product say it too.

## Requirements

- **A new product requires `bazis-front>=0.8.0`** (it was 0.7.0); `bazis>=2.19.1` is
  unchanged.

## Upgrading

- A product whose frontend is upgraded to bazis-front 0.8.0 follows the rules of the
  frontend: `bazis_front update`, then `contract`, `check`, `screens`, `e2e` and `shots`.
- The projects already created keep their `.env`, `project.env` and apps: nothing is
  rewritten. A project that has bazis-users and no route of its users adds
  `users/routes.py` and `users/router.py` as `add_packages` writes them (the sample of
  bazis-front has the same files) and registers `users.router` in its root router.
- A product that needs a second language lists it in `BS_LANGUAGES` and in `languages` of
  `spec/product.yaml` itself.
