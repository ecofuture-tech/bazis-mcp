# bazis-mcp 2.11.0

How each tool works and what it refuses is in the guide,
[bazis/contrib/mcp/AGENTS.md](../../bazis/contrib/mcp/AGENTS.md).

## Features

- **The database of a new project is on a server that was chosen.** `create_project` takes
  `database`, the `host:port` of the PostgreSQL server that the user chose. The server named
  by the environment of bazis-mcp (`BS_DATABASES__DEFAULT__HOST`,
  `BS_DATABASES__DEFAULT__PORT`) is used as before, and a `database` other than it is
  refused. The server chosen, by either, is written in `.env` at once, also when the
  database is not created there (unreachable, failed, taken): `manage.py` and the other
  commands run outside bazis-mcp use it. Without either the call is refused before anything
  is written: the default of the skeleton, localhost:5432, is often the server of other
  projects, and a project created that way put its database there.
- **`clean_project()`** removes the temporary files and the outputs of the builds and the
  tests, which the commands make again: `.scratch/`, `frontend/dist/`,
  `frontend/test-results/`, `frontend/playwright-report/` and
  `frontend/node_modules/.vite-e2e/`, those the project has (a symbolic link itself). A
  client without a shell can clean a project now; `delete_file` still deletes one file.
- **The rules of every project** (`bazis://rules`):
  - the files of guests are the anonymous uploads of bazis-uploadable 2.8, never a file in
    JSON: `BS_BAZIS_FILE_UPLOAD_ANONYMOUS=true` with a size limit, a body of
    `list[UploadedFileId]` (the tokens the uploads answered), attached with
    `FileUpload.objects.anonymous(tokens)` for a guest and by id among his own files for a
    user; the clean-up command `uploadable_clean_anonymous` in cron and the limit and the
    address of the client at the proxy go to Left for you;
  - an amount in the text of a notification is `number_format(amount, decimal_pos=2,
    force_grouping=True)`, in the language of the user;
  - `clean_project` removes `.scratch/` with the outputs of the builds and the tests.
- **The rules of the frontend** (`bazis://rules/frontend`):
  - the specs are checked with the tool `front_check`, never `bazis_front check` through
    `run_command`;
  - a choice of the body of an action is the `TextChoices` of the model, which bazis 2.21
    labels, never a `Literal` (S058); a long text of a body has no `max_length`;
  - the specs of bazis-front 0.9 say the files of a public form (`FilesField`, with the
    anonymous uploads on, S057), an export (the form of an action that answers a file,
    `access_action` view, its rows of `restrict_queryset`) and a flow of several users
    (`as: <role>`, `remember` of what the server made, never the echo of a text typed);
    after the update to 0.9 a custom screen or test of the product that did them becomes
    the spec.

## Changes

- **`create_project` needs the name of the product** in a directory that names none: without
  `name`, a directory named `app`, `src`, `project`, `backend` or `service` is refused
  before anything is written (the package and the database of every such project were
  `app`, `app_2`...). The instructions of the server and the prompt `new_project` say to
  pass `name` and `database`.
- **The catalog** describes the latest releases: bazis 2.21.0 (it was 2.19.1: the labels of
  the choices of a body, `enumDict`), bazis-uploadable 2.8.0 (it was 2.7.0: the anonymous
  uploads), bazis-async-request 2.6.1 (it was 2.5.0), bazis-front 0.9.0 (it was 0.8.0: the
  files of the public forms, the exports, the scenarios of several users, S057, S058); the
  other packages are unchanged.
- The rules are shorter where they repeated the descriptions of the tools and the guides,
  so that the result of `create_project` for a product keeps a tenth of the limit of the
  clients free.

## Requirements

- **A new project requires `bazis>=2.21.0`** (it was 2.19.1) and, with a frontend,
  **`bazis-front>=0.9.0`** (it was 0.8.0).
- The files of guests need bazis-uploadable 2.8.0 (the anonymous uploads), which the
  catalog describes; a project adds it as any package.

## Upgrading

- `create_project` without `database` from a server whose environment names no PostgreSQL
  server is refused now: the client asks the user for the server and passes it as
  `database`. A server started with `BS_DATABASES__DEFAULT__HOST` or
  `BS_DATABASES__DEFAULT__PORT` in its environment works as before, and `.env` of a new
  project names that server.
- `bazis new` of bazis-cli writes `.env` and creates the database as before:
  `scaffold.create_database` is unchanged, and the new keyword `database` of
  `scaffold.write_files` defaults to the server of the skeleton, localhost:5432.
- The projects already created keep their `.env`: nothing is rewritten.

## Known limitations

- `bazis new` of bazis-cli 2.6.1 still writes localhost:5432 in `.env` unless its
  environment names a server: only `create_project` refuses a server nobody chose.
- Two tests of bazis-cli 2.6.1 fail with this release as with 2.10.1:
  `test_new_with_a_language` (stale since bazis-mcp 2.10.0) and
  `test_requirements_are_the_latest_releases` (bazis-cli pins `bazis>=2.16.0`); its minimums
  are raised in bazis-cli separately.
