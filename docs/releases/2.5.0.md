# bazis-mcp 2.5.0

How each tool works and what it refuses is in the guide,
[bazis/contrib/mcp/AGENTS.md](../../bazis/contrib/mcp/AGENTS.md).

## Features

- **The project of the conversation.** A client connects `uvx bazis-mcp` without any
  setting and asks for an application; the server creates it and goes on with the next
  changes in the same conversation (the project served changes without a restart):
  - `create_project(directory, description, name=None, frontend=True, language=None)` —
    a new project in a new or empty directory, served from then on: the skeleton,
    `.venv` from PyPI, the database (a free `<name>_N` when the name is taken by another
    project), the ports; all or nothing.
  - `use_project(directory)` — an existing project, served from then on.
  - `project_status()` — the facts of the project served, with the names of the
    variables of `.env`, never their values.
  - `check_machine()` and `install_tools(names, confirmed_by_user=False)` — the programs
    a project needs on this machine, installed from a closed table (Homebrew, apt) only
    once the user agrees.
  - The resources `bazis://rules` and `bazis://rules/frontend`, the prompts
    `new_project(description)` and `change_project(request)`, and the instructions of the
    server with the order of the work.
- **The work on the project for a client without a shell** (Claude Desktop), never a
  command or a path of the caller outside the project:
  - `add_packages(names)` — Bazis packages of the catalog and those they require, added to
    `requirements.txt` and installed into `.venv`.
  - `run_command(kind, args=[])` — a command of a closed table (`manage`, `pytest`, `pip`,
    `npm`, `npx`) as argv without a shell, with a timeout and its progress.
  - `start_server(which)`, `stop_server(which)`, `server_logs(which, lines=100)` — the
    backend and the dev server of the frontend in the background.
  - `read_file`, `write_file`, `delete_file`, `list_files` — the files of the project
    directory.
- The skeleton of a new project, the rules of Bazis for an agent and its tasks are moved
  here from bazis-cli, which builds its commands on them: `bazis.contrib.mcp.scaffold`,
  `bazis.contrib.mcp.rules` (`RULES`, `FRONTEND_RULES`) and `bazis.contrib.mcp.prompts`.
  Nothing of them imports Django: `scaffold.valid_package_name`,
  `scaffold.product_language` and the checks of a new project run with the Python of
  the project.

## Changes

- bazis-mcp depends on python-dotenv (the names of the variables of `.env`) and on anyio
  (the progress of `run_command`, already a dependency of mcp).
- bazis-mcp no longer depends on bazis: the server never imports the core, it runs the
  project tools with the Python of the project (`--python`, else `.venv`), so
  `uvx bazis-mcp` installs only the server. bazis is in the extra `test`.
- The `.env` of a new project has `E2E_PASSWORD`, the password of the test users of the
  end-to-end tests, given to the commands and hidden in their output.
- The skeleton of a new project requires bazis 2.16.0 and bazis-test-utils 2.5.2.

## Limits

- pip installs only into the Python of the project (`.venv` or `--python`, never that of
  bazis-mcp) and only requirements of PyPI.
- `run_command` takes plain arguments that stay in the project, and never `--basetemp`
  of pytest nor `--output` of `npm run test` and `e2e` as arguments (a configuration may
  set them: that of the project, or one given with `-o`, `-c` or `@<file>`); npm and npx
  never download a tool.
- `.env` is never read nor written; `.venv/`, `.git/`, `contract/` and the `generated/`
  directories are never written nor deleted.
- On Windows only the process itself of a server or a command is stopped, not its group:
  the servers and the long commands are not supported there.
- A call that comes while bazis-mcp ends (up to 10 seconds after the signal) may leave
  its process running.

## Breaking changes

- A server started without `--project-dir` in a directory without `manage.py` serves no
  project: every tool but `create_project` and `use_project` answers "No project: call
  create_project or use_project" (before, the current directory was taken as the project,
  and the catalog tools read the packages of the Python of the server). Pass
  `--project-dir` for a project whose `manage.py` is elsewhere.
- The tools are no longer all read-only: `create_project`, `use_project`,
  `install_tools`, `add_packages`, `run_command`, `start_server`, `stop_server`,
  `write_file` and `delete_file` are not. A client that allows every tool of the server
  without asking now allows these too.
