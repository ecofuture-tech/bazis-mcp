# bazis-mcp 2.5.0

## Features

- **The project of the conversation.** A client connects `uvx bazis-mcp` without any
  setting and asks for an application; the server creates it and goes on with the next
  changes in the same conversation (the project served changes without a restart):
  - `create_project(directory, description, name=None, frontend=True, language=None)`
    writes the skeleton in a new or empty directory (an absolute path; a temporary
    directory, the home directory and a directory inside another project are refused),
    installs `.venv` from PyPI, checks the project package and the language with the
    Python of the project, creates the database when PostgreSQL is reachable, chooses the
    ports and serves the project; a failed step leaves the directory as it was. It returns
    the facts, the `rules` (`RULES`, with `FRONTEND_RULES` for a product with a frontend)
    and `next_steps`, the task of building the project. It is the only tool that reaches
    outside the machine (`openWorldHint`).
  - `use_project(directory)` serves an existing project (the directory of its
    `manage.py`) and returns its status and its `rules`; the project served changes only
    once its status is read, and the project of the command line keeps its `--settings`
    and `--python`. `create_project` and `use_project` run one call at a time.
  - `project_status()`: `directory`, `settings`, `python`, `frontend`, `ports` (null
    when `.bazis/ports.json` cannot be read) and `env_keys`, the names of the variables of
    `.env` read with python-dotenv (a value in quotes on several lines is not taken for
    variables), never their values; a `.env` that links outside the project is not read
    (`env_keys` null, `env_reason` says why).
  - The resources `bazis://rules` and `bazis://rules/frontend`, the prompts
    `new_project(description)` and `change_project(request)`, and the instructions of the
    server with the order of the work (a new or an existing project, the rules, the
    project directory as the boundary of the files, `.env` never read, the summary).
  - `project.inside(path)`: a path of the project resolved with its symbolic links, or an
    error outside it; `project_status` reads `.env` only through it.
- `scaffold.valid_package_name(name, python)` checks the modules a project package must
  not hide in the Python asked (`python -I`), by default the Python running it: in a
  server without Django, `create_project` checks the name again with the Python of the
  project after `.venv`, so `django` or `bazis` never become the project package.

- The skeleton of a new project, the rules of Bazis for an agent and its tasks are moved
  here from bazis-cli, which builds its commands on them: `bazis.contrib.mcp.scaffold`
  (the files of a project, `.venv` with its minimums raised to the installed releases,
  the database, `.bazis/ports.json`, the check of Node.js), `bazis.contrib.mcp.rules`
  (`RULES`, `FRONTEND_RULES`, with the same texts) and `bazis.contrib.mcp.prompts` (the
  tasks of a new project, of a package added and of a change, and the steps of a
  frontend). Nothing of them imports Django: `scaffold.product_language(code, python)`
  reads the language of Django of a code with a Python that has Django, such as that of
  the project, and `scaffold.set_language(directory, language)` writes it in
  `project.env` of a skeleton, which `write_files` writes in English.

## Changes

- bazis-mcp depends on python-dotenv (the names of the variables of `.env`).
- bazis-mcp no longer depends on bazis: the server never imports the core, it runs the
  project tools with the Python of the project (`--python`, else `.venv`), so
  `uvx bazis-mcp` installs only the server. bazis is in the extra `test` (the sample
  project and the skeleton of the tests). A server run without a Python of the project
  needs the packages of the project in its own Python, as before.
- The skeleton of a new project requires the latest releases, whose guides the catalog
  describes: bazis 2.16.0 (`scaffold.REQUIREMENTS`, also in the extra `test`) and
  bazis-test-utils 2.5.2 (`scaffold.REQUIREMENTS_DEV`).

## Breaking changes

- A server started without `--project-dir` in a directory without `manage.py` serves no
  project: every tool but `create_project` and `use_project` answers "No project: call
  create_project or use_project" (before, the current directory was taken as the project,
  and the catalog tools read the packages of the Python of the server). Pass
  `--project-dir` for a project whose `manage.py` is elsewhere. The tools are no longer
  all read-only: `create_project` and `use_project` are not.
